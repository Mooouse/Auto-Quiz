# Архитектура AUTO QUIZ

Игра использует предоставленную платформу через `kit: code`. `scripts/setup.mjs` проверяет хеш архива, распаковывает его в `.platform`; файлы платформы не изменяются. Vite использует её штатные aliases, валидатор конфигурации и `virtual:gp/game`. Приложение DOM/CSS, без 3D или тяжёлого игрового движка.

| Модуль | Ответственность |
|---|---|
| `data/catalog.ts` | Схема, уникальность, фильтры, минимальный размер пула |
| `domain/questions.ts` | Перемешивание, очередь без повторов, недавние машины, похожие варианты |
| `domain/answers.ts` | Строгая нормализация и проверка алиасов |
| `domain/scoring.ts` | Базовые очки, серии, скорость, XP и звания |
| `domain/session.ts` | `LocalSession`: вопрос → ответ → следующий вопрос → результат; активные часы |
| `domain/profile.ts` | Статистика, коллекция, достижения и восстановление сохранения |
| `services/storage.ts` | `ProfileRepository` и реализация через localStorage |
| `services/catalog-store.ts` | Загрузка JSON/PNG, декодирование, кэш 6 фото, предзагрузка, импорт IndexedDB |
| `services/platform.ts` | Граница GameHost / будущего SDK |
| `services/audio.ts` | Короткие синтезированные эффекты через аудио-шину платформы |
| `ui/app.ts`, `ui/styles.css`, `ui/icons.ts` | Представление и пользовательские действия |
| `strings/en.yaml`, `strings/ru.yaml` | Все основные тексты интерфейса (JSON — допустимый YAML) |

`LocalSession` принимает часы и генератор случайных чисел извне. Загрузка PNG и пауза не расходуют время. После ответа сессия блокирует повторную отправку. Профиль сохраняется сразу, результаты сессии учитываются один раз. Завершённые рекорды хранятся отдельно для 12 сочетаний режима и формата. Выйти досрочно можно с сохранением XP, но без обновления рекорда.

Модальные окна живут вне перерисовываемой поверхности: асинхронная загрузка PNG не уничтожает подтверждения. Во время импорта запуск сессии и навигация блокируются до атомарной замены набора. Коллекция показывает только страницу записей; браузер не декодирует всю базу сразу.

## Будущий онлайн

`SessionController` отделяет интерфейс от локальной реализации. Для сетевого клиента следует добавить асинхронный transport/controller, подписки на серверные снимки и состояния подключения. Текущий контракт синхронен, поэтому перед интеграцией транспорта потребуется расширить именно этот слой и обработчики ожидания в UI; алгоритмы одиночной игры и каталог не нужно смешивать с сетью.

Сервер должен владеть вопросами, принимаемыми ответами, дедлайнами, очками и рейтингами. Нельзя доверять времени, счёту или открытому клиентскому JSON. Локальные рекорды не являются соревновательными и не должны переноситься в онлайн-рейтинг. Звания за XP уже отделены от будущих онлайн-рангов. Матчмейкинг, комнаты, авторизация и лидерборды сейчас отсутствуют.

## CrazyGames

По заданию SDK подготовлен как отдельная точка интеграции, но текущий `game.yaml` имеет `channel: web`. Сборка не отправляет реальные CrazyGames SDK-события и не содержит рекламы. Предоставленный архив содержит адаптер портала, который перед включением нужно сверить с актуальными официальными документами:

- https://docs.crazygames.com/sdk/intro/
- https://docs.crazygames.com/sdk/game/
- https://docs.crazygames.com/requirements/technical/

На момент проверки документации: жизненный цикл SDK v3 включает инициализацию и `gameplayStart` / `gameplayStop`. Переключение фокуса само по себе не должно порождать эти SDK-события; локальная пауза и отправка событий на портал должны быть согласованы отдельно. Также нужна обработка mute портала. Не включайте канал автоматически, не проверив поведение архивного адаптера и portal preview.

Сборка использует относительные локальные URL и может размещаться во вложенном каталоге. Нужны финальные фотографии, реальные мобильные устройства, проверка SDK в портальном превью, обложки и окончательный submission-пакет. Эта версия не заявляется сертифицированной или готовой к публичной отправке.
